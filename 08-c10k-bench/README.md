# 第 8 节：C10K 压测

## 为什么学

C10K（1999 年 Dan Kegel 提出）问的是：一台服务器怎么同时服务 1 万个连接。前面每一节都给出了一种模型，这一节用同一个压测把它们放在一起比，
用数字回答"为什么最后是 epoll"。

---

## 要学的内容

1. 用 epoll 写压测客户端：非阻塞 `connect`（`EINPROGRESS` → 等 `EPOLLOUT` → `getsockopt(SO_ERROR)` 确认）
2. 客户端的端口限制：本机 `ip_local_port_range` 是 32768–60999，连同一个服务端地址最多约 2.8 万个连接；可以用多个服务端端口或 127.0.0.x 多个地址绕过
3. `listen` 的 backlog 和 `somaxconn`（本机 4096）：瞬间建 1 万个连接时 accept 跟不上会怎样
4. 测什么：建连耗时、每个请求的延迟分布（p50/p99）、服务器 CPU 时间（`perf stat`、`/proc/<pid>/stat`）、内存（RSS）

## 任务

### 任务 A：压测客户端 `loadgen.c`

参数：服务端地址、连接数 N、每个连接每秒发几次、持续时间。每个连接发一条带时间戳的消息，收到回显后算延迟。
结束时打印成功连接数、总请求数、p50/p99 延迟。

### 任务 B：对比

N = 100、1000、10000，分别压第 2 节线程版、第 4 节 select 版、第 5 节 poll 版、第 6/7 节 epoll 版，填一张表：

| 模型 | N | 建连成功 | p50 | p99 | 服务器 CPU 时间 | 服务器 RSS |
|------|---|----------|-----|-----|-----------------|------------|
