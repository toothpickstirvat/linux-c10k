# 第 7 节：epoll 边沿触发（ET）

## 为什么学

边沿触发只在 fd 从"不可读"变成"可读"（有新数据到达）的那一刻通知一次。通知次数少，但规则严格：
**收到通知后必须一直读到 EAGAIN**，否则剩下的数据不会再通知，连接就卡死了。Go、nginx 用的都是 ET。

---

## 要学的内容

1. `ev.events = EPOLLIN | EPOLLET`，fd 必须是非阻塞的（为什么？）
2. 读到 EAGAIN 为止的循环；accept 也一样，listenfd 用 ET 时要循环 accept 到 EAGAIN
3. `EPOLLRDHUP`：对方关闭写端（半关闭）时通知
4. `EPOLLONESHOT`：通知一次后自动禁用，多线程处理同一个 epoll 时防止两个线程同时处理一个连接
5. 公平性：一个连接数据很多，一直读到 EAGAIN 会饿死别的连接，怎么办
